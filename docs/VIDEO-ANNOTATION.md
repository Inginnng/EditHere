# 视频标注

**0.10.0 当前为本地测试版，尚未公开发布。** 本轮改进包标记为 `0.10.0-pause-update`，应用版本仍是 `0.10.0`。视频标注把一段视频中多个时间点的修改意见集中保存在一个项目里。源视频以地址引用，开始实际批注时才保存画面截图；导出的 JSON 在每帧内复用图片标注结构，让 AI 同时根据时间、画面和坐标定位修改点。

## 操作流程

1. 打开视频文件，或打开已保存的 `.edithere` 视频项目。
2. 点击“播放”查看视频；在目标画面点击“暂停”，或拖动时间轴、使用 `−1s` / `+1s` 定位后停住画面。
3. 暂停仍显示视频画面。确认画面和时间后，添加第一个实际点、框或全局批注，程序才保存这一帧的截图并进入批注画布，后续批注沿用现有工具。
4. 继续播放或定位到其他时间点，添加下一组批注时保存对应截图。同一画面的多个批注共用一张截图。
5. 使用“已标注画面 X 个”下拉框，或直接点击时间轴上的青色下尖标签，回到已有批注的时间点。条目显示时间和批注数量，例如 `00:12.540 · 2条批注`。
6. 保存项目以便继续编辑，或导出 JSON。与 AI 协作时点击“完成并返回 AI”，一次提交这些时间点的反馈。

时间轴定位不是精确的上一帧/下一帧命令。实际标注时间取自截获画面的时间戳，避免播放进度条的时间与截图不对应。

视频画面由普通控件绘制，帧在后台线程转换，不再使用 `QVideoWidget` 的原生窗口；后者会把批注画布也变成原生窗口，导致画上的框不显示。

播放和暂停使用一致的按钮背景；播放按钮、时间显示和已标注画面列表预留稳定宽度，视频播放与标注画布共用同一显示区域。打开首帧、普通暂停、前后定位或拖动时间轴只让视频停在目标画面，不立即截图。暂停中点击 `−1s` / `+1s` 保持暂停，播放中点击则跳到目标画面后暂停；再次点击“播放”或按空格继续播放。连续点击 `−1s` / `+1s` 会按待定位目标累计步进。

选择批注模式、缩放或平移都不会保存新截图。暂停提示“已暂停 · 开始批注时保存当前画面”；只有首次实际点、框或全局批注才保存这一帧。已有批注帧的下拉列表直接恢复保存的截图和批注。保存项目或导出 JSON 处理已有批注帧，不会把当前仅暂停查看的画面自动加入项目。

同分辨率换帧保留当前缩放、平移、标注工具与侧栏状态，不强制激活窗口或转移批注输入焦点。快速换帧时，分块分析等待定位稍作停顿后执行，减少重复处理。

## 文件与源视频

项目记录源视频地址，不把整段视频装进 JSON。截图在开始实际批注时创建，单纯打开、播放、暂停和定位不会积累截图，因此项目大小主要随批注画面数量增长。截图以 Base64 内嵌时，图片数据约增加三分之一体积。

视频移动或删除后，已保存的截图和批注仍可查看。点击“重新指定视频”选择对应视频，恢复播放与继续定位；应选同一内容的视频，否则旧时间戳可能指向不同画面。

导出时 `frames[n].feedback.image` 保存内嵌截图；`frames[n].imageFile` 如存在，记录 JSON 同目录截图文件名。只导出不内嵌图片的 JSON 时，分享给 AI 应保留这些同目录截图文件，或重新导出内嵌图片的版本。

## JSON 结构

```json
{
  "schemaVersion": "video-feedback-1",
  "video": {
    "source": "E:/videos/demo.mp4",
    "durationMs": 30000,
    "width": 1920,
    "height": 1080
  },
  "frames": [
    {
      "id": "frame-12540123",
      "timestampMs": 12540,
      "timestampUs": 12540123,
      "imageFile": "frame-12540123.png",
      "feedback": {
        "annotationSpace": "result",
        "image": "data:image/png;base64,...",
        "objects": [
          {
            "source": {"x1": 120, "y1": 80, "x2": 360, "y2": 160},
            "movements": [],
            "annotations": ["这里的标题出现得太早，延后到下一秒"]
          }
        ]
      }
    }
  ],
  "objects": [
    {
      "source": {"x1": 120, "y1": 80, "x2": 360, "y2": 160},
      "movements": [],
      "annotations": ["这里的标题出现得太早，延后到下一秒"],
      "timestampMs": 12540,
      "frameId": "frame-12540123"
    }
  ]
}
```

上例中的 `...` 仅是文档占位；真实导出包含完整的 Base64 图像数据。

`timestampMs: 12540` 表示视频起点之后 `00:12.540`。`timestampUs` 保留实际截帧时间的微秒精度，`timestampMs` 是其除以 1000 后的整数部分；它们是媒体相对时间，不是日期或系统时间。AI 应使用 `frameId + timestampMs + 坐标` 定位，相同坐标在不同时刻可以有完全不同的修改意见。

`source`、`movements.to` 都使用对应帧截图的像素坐标，原点在左上角。矩形右下边界不包含自身，上例区域宽 `240`、高 `80`；`source: null` 表示该时间点的全局意见。坐标不能直接当作屏幕坐标或网页 CSS 像素。

点批注也使用 `source`，其 `x1 == x2`、`y1 == y2`，表示该像素位置而不是需要修改的空矩形。连接器会将其明确描述为“原图点”。

每帧的 `feedback` 是一份现有图片反馈；根 `objects` 是相同对象的展开索引，给每个图形对象直接附上时间戳，便于只遍历对象的工具读取。AI 不应将这两处重复记录视为两次修改要求。

## AI 读取

MCP 连接器的视频摘要按帧给出时间、坐标、文字和截图入口。`includeImage: true` 时每张图像前都有帧 ID 与时间，最多直接附 8 张截图；超过图片数量或大小上限时会显式列出尚未附图的帧索引。完整截图与批注仍保存在 JSON 或同目录截图文件中，AI 应按 `frames[n]` 继续读取。

大量批注的摘要也会明确报告未展开部分。摘要只是一份阅读入口；定位和修改应以完整反馈中的时间戳、截图与批注为依据。
