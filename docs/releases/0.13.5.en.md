0.13.5 fixes scrolling capture stopping at startup with “Unable to exclude EditHere windows from scrolling capture” on macOS (#54).

- **Window exclusion**: shareable content now includes hidden windows. If EditHere is absent from the application list, the filter also checks window owners for its application handle.
- **Capture fallback**: if the system still omits the application, capture continues through the existing path that temporarily hides scrolling capture controls. Diagnostics record the filtering mode used.
- **Error handling**: disconnected displays, changed resolution, recording permission errors and capture failures still produce errors.

New regression cases cover first-frame capture without an application entry, application exclusion and error paths. Actual scrolling and stitching on the original macOS 27.0.1 device still require confirmation.
