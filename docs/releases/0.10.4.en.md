# 0.10.4

- Installation, updates and uninstallation share a maintenance transaction with a per-target lock, persistent logs, interrupted-operation recovery, rollback of system registration and shortcuts, and file and runtime version checks. User files are preserved, obsolete packaged files are removed, and a failed uninstall can be restored and retried.
- In-app updates wait until the installer is ready before closing the application. Preparation failures, cancellation and timeouts keep the application running; the next launch reads the installation result.
- Fixed Windows installation failing when the downloaded installer is inside its destination or a subdirectory. Program files are replaced individually according to their manifest; the installer and user files stay in place, with rollback on failure.
- Installation failures identify the failed step; a first installation no longer claims that an old version was preserved.
- Existing installations show “Update existing version”, preserve the recorded location and options, and proceed directly to update progress after confirmation. Reinstalling the same version follows the same flow.
- Fixed native System.dll being resolved as a .NET compiler reference, which broke installation and recovery. Shell notification failures now produce a warning without interrupting completed registration.
- Update checks are enabled by default after the first interactive launch, with an Update now / Skip dialog when a newer version is available. Capture, AI sessions, the guide and other dialogs defer the reminder. No dialog appears when no update exists or a check fails; existing disabled preferences are preserved.
- Updates reuse the GitHub/Gitee checks, SHA-256 verification and unsaved-work confirmation. Skipping keeps the app running, and downloads can be cancelled.
- Added regression coverage for installers occupying their own destination and startup update reminders.
