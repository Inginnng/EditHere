This update fixes EditHere being closed together with the AI tool that launched it, and recovers the finished annotation feedback when the command receipt is interrupted.

- **The annotation window no longer disappears mid-session**: EditHere launched by an AI tool used to stay bound to its caller, so quitting the caller closed it too, taking the annotation window with it and making the written feedback hard to confirm. The desktop now starts independently and confirms it has left the caller before showing its window. When the caller does not permit that, EditHere asks you to open it manually and retry instead of failing silently.
- **Feedback is no longer lost to an interrupted receipt**: if the desktop has already written the feedback file but the CLI receipt never arrives, the connector now reads this session's feedback file, checks it and returns the result as usual, noting that this only confirms the feedback was saved.
- Cancelled, timed-out and otherwise rejected requests still report their original outcome; a file with the same name on disk never turns them into a success. Missing, truncated or non-regular files, and structurally incomplete feedback, still fail, and you are told that your edits in EditHere are preserved.
- After a connector restart, the feedback path returned when the session started is read first, to see whether a complete feedback file already exists before starting another annotation, avoiding duplicate work.
- Added session logs for start, feedback commit, completion and normal exit, telling "never submitted" apart from "submitted but the connection dropped". The logs never contain annotation text and are never uploaded automatically.
