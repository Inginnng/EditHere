0.13.1 adds HDR / Advanced Color handling to Windows screen capture, fixes Linux portal and settings compatibility, and corrects the project README files.

- **Screenshot colors**: ordinary and scrolling captures on Advanced Color displays use floating-point capture and the monitor's current SDR white level to produce standard sRGB images. This avoids washed-out dark text and light-gray backgrounds clipping to white. SDR displays retain the existing capture path.
- **Capture reliability**: handle per-output rotation, native resolution and texture row pitch. Scrolling capture reuses its capture session and releases it when finished. Floating-point capture failures are reported and logged rather than presented as successfully corrected images.
- **Linux compatibility**: save other settings when the desktop lacks the global-shortcut portal, with a notice to use the tray or system shortcuts. Follow legacy portal request handles, open completed system selections directly in the editor, and restore the editor after failed or cancelled capture. Denied authorisation and shortcut conflicts still reject the save.
- **Documentation**: remove merge-conflict markers from both README files, restore the desktop / Web comparison tables and retain accurate descriptions of the three interface languages, optional API requests and authenticated in-app updates.

Color conversion, real GPU pixels, capture-overlay exclusion and repeated capture passed regression tests. HDR is not enabled on the local test display; acceptance on the device reported in #68 is still pending, so the issue remains open. Output is standard sRGB; HDR highlights beyond SDR are not preserved losslessly.
