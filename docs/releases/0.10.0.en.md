This release adds video annotation and scrolling capture, and fixes a number of stability issues.

### Video annotation

- Open or drop in a video to play it, with built-in playback and audio, a timeline, and one-second steps forwards and backwards. After pausing, the existing point, rectangle, text and component tools are available to write your comments on the frame you are looking at.
- Annotated frames are marked on the timeline with a cyan downward-pointing tag whose tip meets the progress bar; hovering enlarges it, and clicking returns to that frame and its annotations. The “Annotated frames” list jumps the same way.
- The playback view and the annotation canvas share one display area. The play and Pause buttons share one background and keep a stable width, so switching state no longer shifts the timeline and the buttons beside it.
- A saved `.edithere` video project references only the source video's location and stores the annotated frames' screenshots and editing state. If the source video moves or goes missing, the saved screenshots are still viewable, and you can point the project at the video again to resume playback.
- Exporting `video-feedback-1` JSON reuses the existing image feedback structure for each frame, including that frame's real timestamp and screenshot, with `timestampMs` and `frameId` attached to expanded graphic objects. Comments left at the same coordinates at different timestamps are kept separately.
- The command-line tool and the MCP connector support video sessions and project export. When the screenshots exceed a tool's per-call attachment limit, the frame indices to read next are listed explicitly, and the complete feedback is still saved in the JSON.

### Scrolling capture

- After selecting a scrollable region, click “Scrolling capture” in the toolbar or press `L` to start. A translucent grey mask covers everything outside the selection, a hollow border marks the region actually captured, and a compact toolbar sits below the selection.
- Capture works in both directions, and content that has already been captured is not stitched twice. The preview on the right keeps a fixed width and extends at both ends, with a green box marking the current position; once it exceeds the screen it shows the source region near the current position.
- While running, dragging the move handle moves the selection along the capture direction, keeping the captured image and continuing to append. After stopping, the selection can be moved freely and resized by dragging its edges. Switching between vertical and horizontal, or actually changing the selection's size, starts a new round from the current frame.
- The scissors menu immediately cuts away the pixels beyond the current frame's top and bottom boundaries — left and right in horizontal mode — and automatic cropping can be enabled while scrolling back. Editing, copying, saving and pinning all use the cropped source image.
- New scrolling capture settings: the default direction, automatic cropping and Ultra-long capture mode can be changed in the settings, and saving uses the ordinary dialog to choose a location.
- The optional “Ultra-long capture” mode reaches up to 2 million pixels on a single axis, and results beyond the editor's image limits are saved as tiled PNG. Past a 32767 pixel edge or 32 million pixels a PNG can still be saved, but the result can no longer be edited, copied or pinned directly.
- New capture backends for macOS ScreenCaptureKit, Linux X11 and Wayland Portal/PipeWire share the same preview, menu and stitching. Automatic scrolling on macOS needs Accessibility and event-posting permission, X11 needs XTEST, and Wayland currently supports manual scrolling.

### Diagnostic log

- The settings add a “Diagnostic log” page that opens the local log directory or exports a text report for a problem report. A separate QtCore module records the runtime environment, operation state and errors, rotates the logs automatically, and never collects screenshots or annotation text — nor uploads anything on its own.

### Fixes

- Fixed scrolling capture quitting when the direction was switched while preparing, an old callback from an ordinary screenshot affecting a new session, and a pinned annotation overwriting unsaved content.
- Fixed the previous video's frame reappearing in the background after switching videos, the status interface not reporting unsaved changes while previewing a video, and dropping in a malformed image being able to close the application.
- Fixed scrolling capture reporting “cannot match the adjacent frame” as soon as scrolling began: manual scrolling now stitches as you scroll, with the whole stitched image shown live on the right, and scrolling too fast to match asks you to scroll back a little.
- Fixed annotations stuttering after pausing a video, and a drawn rectangle not appearing; annotation marks on the timeline are now clickable and return straight to that frame and its annotations.
- Fixed concentric scaling being lost in the feedback, nearby fractional coordinates being merged, and annotation positions disagreeing after several moves.
- Fixed the text recognition helper staying busy after it failed to start, a reused recognition window still showing the previous image, and an older asynchronous detection result overwriting a later screenshot.
- Saving a capture style now preserves border and shadow colour and opacity.
- Feedback import now checks invalid coordinates and cumulative counts up front, and bounds the temporary memory used when rebuilding overlapping regions.
- Desktop communication now clears oversized and idle requests and receives fragmented paths containing Chinese characters correctly; the MCP connector preserves Chinese text in chunked output and reports abnormal exits and timeouts correctly.

### Platforms and verification

- The full Windows regression passed 24/24 groups, and the whole scrolling capture flow was verified against a real external window. The full Ubuntu 24.04 regression passed 23/23 groups, and the X11 backend verified native pixels, wheel events, 1×/1.5×/2× scaling and manual capture without XTEST inside Xvfb.
- The Wayland authorized-session and pixel-mapping tests passed 16/16, and the native PipeWire client compiles and passed runtime initialisation checks; it has not been accepted on a real Wayland desktop yet. The macOS implementation is in place and compiles in the macOS build, without acceptance testing on a physical Mac yet. The decoding libraries video playback needs ship with the package, while text recognition uses the recognition capability already installed on the system, with no network access and no upload.
- The scrolling capture suite covers 2 million pixel ultra-long stitching and tiled PNG export, checked pixel by pixel with an independent decoder.
- Before upgrading, quit the old version normally from the tray and save any unfinished edits, then run the installer or fully extract the new package.
