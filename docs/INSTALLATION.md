# Windows 安装与维护

[开发说明](DEVELOPMENT.md) · [问题归档](REGRESSIONS.md)

安装、程序内更新与卸载共用维护流程。NSIS 负责页面、载荷解包和启动；`packaging/windows/maintain.ps1` 负责程序文件及系统集成事务；`integrate.ps1` 负责当前用户的登记、快照和恢复。保持当前用户安装，无需管理员权限。便携更新执行相同的文件事务，但跳过快捷方式、PATH 和注册表。

## 安装和更新

首次安装显示安装位置及选项。检测到已安装时显示“更新现有版本”，自动沿用已有安装位置和选项，不显示位置选择页；同版本重复运行也执行更新。程序内更新直接显示进度，不重复走首次安装页面。已有版本高于安装包版本时停止，提示已安装更新版本。

1. 用户运行的安装包在原处执行；安装包位于程序目录或其子目录内也能正常安装，完成或卸载时保留用户下载的安装包。
2. 将新版本完整解包到同级暂存目录，安装版同时生成卸载程序。暂存目录仅用于经过校验的程序载荷。
3. 维护进程取得按目标目录区分的独占锁，普通安装另取得当前用户系统集成锁，读取目标之外的持久事务记录。独立安装先恢复之前未提交的操作；程序内更新若发现未恢复事务，会保留当前程序并要求独立安装恢复。其他目录也有未恢复的系统集成事务时，不允许覆盖其登记。
4. 校验新包的文件清单、SHA-256、路径和版本，检查空间及目录可写性。目标根目录与受管理路径不允许重解析点；不遍历未知用户子目录。新程序文件与未知文件或目录重名时，在写入前明确失败。
5. 程序内更新确认维护进程已准备就绪后才退出；等待或准备失败会保留正在运行的程序。取消请求在退出交接之前生效。
6. 保存当前系统登记和快捷方式，关闭运行实例。旧、新文件清单生成完整操作计划，未知用户文件与安装包不读取、不复制、不参与替换。
7. 持久记录每个程序文件的操作意图，将旧文件放入备份，再将校验后的新文件写入原位置；最后发布文件清单。完成系统集成后，检查命令行程序能否加载且返回预期版本。
8. 所有必需步骤成功后持久提交事务和结果，再回收旧程序备份。提交前失败按实际文件状态逆序恢复程序文件、登记和快捷方式；不能自动恢复的原文件及后续改动保留并记录路径。提交后的清理失败记录为待清理，不能改称本次安装失败。只清理本次创建且仍为空的目录。

程序根目录保持原位，文件事务使用 `schema=2` 的完整计划恢复；旧 `schema=1` 记录保留专用恢复分支。安装器退出码对应实际维护结果，结果同时写入持久记录。

## 更新交接

Qt 更新器完整下载并验证发行包之后，创建带目标目录、预期版本和随机令牌的请求。NSIS 转交请求编号；维护进程回报 `ready`，Qt 校验身份、写入确认后退出。维护进程在收到确认之前不关闭或替换程序。准备失败、取消或等待超时都不会宣布安装开始。

最终结果保存在 `%LOCALAPPDATA%\EditHere\Installer\Results\last.json`；事务记录和日志在同一维护目录下，位于安装目标之外。下次启动识别与当前目标相符的失败记录，避免把上一轮更新失败当作成功，也避免重复显示同一结果。仅清理可证实由本次流程创建的临时文件，未知用户文件和未恢复的备份保留。

## 卸载

卸载遵循相同的锁、日志、恢复和文件所有权规则。安装清单之外的项目或用户文件保留。卸载失败必须有可重试的状态；不得先移除卸载登记，再无条件宣布文件删除成功。删除和清理按经过验证的目标与文件清单执行。

系统刷新通知使用 .NET 运行时库的绝对引用路径，避免 NSIS 工作目录里的原生同名 DLL 被当成托管库。通知失败记录警告，不把已保存的系统登记或恢复判为失败。

## 验证范围

- `tests/installer_transaction_test.py`：真实 NSIS 原地执行、首次安装、更新现有版本、参数传递和失败路径。
- `tests/installer_ui_flow_test.py`：在独立隐藏 Windows 桌面读取和操作真实窗口，验证首次安装页面、重复安装确认及应用更新直接进入进度。
- `tests/maintenance_test.py`：真实文件事务、旧清单淘汰、未知文件保留、中断恢复、互斥和卸载重试，系统集成使用 JSON 替身。
- `tests/installer_shell_notification_test.py`：使用原生 NSIS System.dll 重现工作目录冲突，验证真实生产通知代码及非致命失败。
- Qt 更新及启动测试：就绪确认、取消、失败和超时不会提前退出，结果记录与提示。
- `tests/installer_package_acceptance.py`：显式提供新旧完整 Windows 程序包后，验证真实 NSIS 安装、升级、便携更新、READY/ACK 与下载清理、卸载以及实际 CLI 运行版本；不跳过运行验证。
- NSIS 与完整包验收中的真实系统集成只写入带隔离标记的测试目录及专用 HKCU 测试键；不修改开发者真实 PATH、默认文件关联和快捷方式。

这些回归用于验证具体故障与生命周期行为。公开发布前仍需在干净 Windows 环境使用最终发行包完成普通安装、旧版升级、程序内更新和卸载验收；本地测试包、隔离回归和正式发行分别记录。
