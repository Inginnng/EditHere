# 多语言（i18n）

EditHere 内置简体中文与英文两套界面。**简体中文是源码里写死的源语言**——`tr("保存项目")`
里的中文就是原文，英文通过翻译文件提供。这样做的原因有两个：现有的单元测试断言的是中文
文案，保持源语言不变可以让它们继续有效；中文文案也不需要经过一次"翻译回中文"的往返而走样。

## 怎么写可翻译的字符串

按代码所在的位置选写法，四条规则覆盖全部情况：

| 位置 | 写法 | 翻译文件里的上下文 |
| --- | --- | --- |
| `QObject` 派生类（带 `Q_OBJECT`）的成员函数 | `tr("保存项目")` | 类名，如 `h2d::Editor` |
| `namespace h2d` 下的自由函数 | 文件内定义一次 `tr` 转发到 `QCoreApplication::translate("h2d", …)`，然后照常调用 `tr("…")` | `h2d` |
| 嵌套在类/命名空间/Lambda 里的 `tr()` | `QCoreApplication::translate("h2d", "…")`（**必须写全**） | `h2d` |
| 既要当数据、又要显示的字符串 | `QT_TRANSLATE_NOOP("EditHere", "色块区域")` | `EditHere` |

自由函数的转发只需要在文件顶部写一次：

```cpp
namespace h2d {
namespace {
// Free functions have no tr(); the enclosing "h2d" context groups them so the
// translation file stays easy to review.
inline QString tr(const char *text) {
    return QCoreApplication::translate("h2d", text);
}
```

不要用自定义宏去包 `tr()`：`lupdate` 扫描的是源代码文本而非预处理结果，宏会让字符串抽不出来。

### 陷阱：嵌套作用域里的 `tr()`

`lupdate` 按**最内层的类或命名空间**推断上下文，运行期却按 C++ 的名字查找规则选函数。
两者只有在"自由函数"和"带 `Q_OBJECT` 的类"这两种情况下才一致。一旦不写全上下文就会
**静默地永远翻译不到**（`.ts` 里有条目、界面上却是中文）。三种出错情形：

| 源码 | `lupdate` 给的上下文 | 运行期实际上下文 |
| --- | --- | --- |
| 没有 `Q_OBJECT` 的普通类（`autostart.cpp` 的 `WindowsRunValueStore`） | `h2d::WindowsRunValueStore` | `h2d` ← 文件内的 `tr` 转发 |
| `.cpp` 里的具名命名空间（`autostart_detail`） | `h2d::autostart_detail` | `h2d` |
| Lambda / 三元表达式里的 `tr()`（`platform_mac.mm`） | 有时是 `h2d`，有时**完全抽不到** | 视外层函数而定 |

规避办法有两类：把字符串提到文件作用域（`autostart.cpp` 用 `verbRead()` 这类小函数把
`tr("读取")` 放在 `h2d` 作用域里），或者干脆写全 `QCoreApplication::translate("h2d", "…")`。
`QCoreApplication::translate("上下文", "原文")` 的两个参数都是字面量时，`lupdate` 会照着
第一个参数写上下文，与所在作用域无关，是最省心的写全方式。

## 实时切换的纪律

界面是用 C++ 构造函数搭出来的，没有 `.ui` 文件，所以 Qt 不会自动生成 `retranslateUi()`。
每个常驻（长生命周期）界面组件必须自己遵守一条纪律：

**把所有 `setText` / `setToolTip` / `setAccessibleName` / `addAction` / `addItem` 集中到一个
`retranslate()` 里，构造函数末尾也调用它，`changeEvent()` 收到 `QEvent::LanguageChange`
时再调用一次。**

```cpp
void SomePanel::changeEvent(QEvent *event) {
    if (event->type() == QEvent::LanguageChange)
        retranslate();
    QWidget::changeEvent(event);
}
```

这样"某个文案在哪里被设置"全局只有一处，不存在"改了构造函数、忘了改 `retranslate()`"的
漂移风险——等同于手写版的 `retranslateUi()`。构造函数负责创建控件并把指针存成成员，
`retranslate()` 只负责把文案刷上去。

`installLanguage()` 负责把事件送到位。Qt 只在**安装**翻译时才会补发 `QEvent::LanguageChange`，
而切回简体中文（源语言）时什么都没装，发布包也可能不带 Qt 自带的 `.qm`；所以
`installLanguage()` 自己发一次这个事件，不依赖那个副作用。事件是排队投递的，界面上看
不出来，但写测试时要给事件循环一次机会（`QTest::qWait(1)`）。

只在使用当时创建、用完即弃的界面（`QMessageBox`、截图覆盖层 `Overlay`、使用引导
`GuideOverlay`、在调用点拼接的错误信息）天然就是实时的，不需要
`retranslate()`。

当前需要维护 `retranslate()` 的组件：`Editor`、`Controller`（托盘菜单）、`Canvas`、
`LayoutCanvas`、`LayoutInspector`、`SettingsDialog`、`VideoPlayback`。

`VideoPlayback` 的 `retranslate()` 由 `Editor::retranslate()` 调用，并按当前播放阶段重建状态
提示，包括正在打开、定位、播放中、暂停、查看已保存画面和播放错误。`Editor::retranslate()` 同时调用
`updateVideoFrames()` 重建已标注帧下拉列表，保留原选中时间点；播放按钮、状态提示和帧列表
都随语言切换更新。

`LayoutCanvas` 的提示语是发给 `Editor` 的一个信号，没法就地重译，所以它按当前状态
（选中 / 画框模式 / 悬停区域）重新 emit 一次，见 `LayoutCanvas::updateHint()`。

## 区域标签是数据，不是文案

`色块区域`、`内容区域`、`整个图片`、`整个屏幕`、`窗口`、`手动区域`、`整个表格`、`表格行`、
`表格列` 这些标签会写进反馈 JSON，是给 Agent 消费的稳定契约，`tests/detector_test.cpp`
与 `tests/layout_test.cpp` 也直接断言这些值。因此：

- 生产这些标签的地方（`detector.cpp`、`table_detector.cpp`、`overlay.cpp`、
  `platform_*.cpp/mm`、`editor.cpp`、`layout.h`）用 `QT_TRANSLATE_NOOP` 标注，**值保持中文不变**；
- 显示它们的地方调用 `h2d::localizedLabel()` 取当前语言的文字。

好处是切换界面语言不会改变导出的 JSON，也不会让 Agent 拿到的字段随用户语言漂移。

## 不要翻译的内容

- 内部标识符：`definition.id`、`method`、`objectName`、`target["source"]` 等；
- 应用名、可执行文件名、注册表/路径片段；
- Agent 协议里的 `message` / `error` 文案（面向 Agent，固定英文）；
- 语言名本身（`简体中文`、`English` 以各自的文字显示，不参与翻译）。

## 构建与翻译工作流

翻译文件在 `app/translations/`，随可执行文件一起编译进 `:/i18n/` 资源。

视频功能的翻译分为三个运行期上下文：`videoproject.cpp` 中项目读取/校验/导出的自由函数使用
`h2d`；播放器类使用 `h2d::VideoPlayback`；打开文件、源视频丢失提示及导出提示使用
`h2d::Editor`。翻译时间戳附近的说明和文件对话框名称时，保留 `%1` / `%2` / `%3` 占位符、
文件扩展名和 `;;` 过滤器分隔符。帧 ID、源视频地址、JSON 字段和批注正文不随界面语言改写。

0.10.0 视频功能新增或改名的 68 条文案已补齐英文，并同步生成预编译 `.qm`；
`check-translations.py --qt D:/Qt/6.8.0/msvc2022_64` 验证 717 条消息全部完成。

```bash
# 抽出/更新待翻译条目（新增或改动了 tr() 字符串后运行）
# 必须显式列出 .mm：lupdate 扫目录时不认 Objective-C++，macOS 的文案会整批漏掉
"D:/Qt/6.8.0/msvc2022_64/bin/lupdate.exe" app/*.cpp app/*.h app/*.mm \
    -ts app/translations/edithere_en.ts -no-obsolete

# 手动检查编译产物（正常构建会由 CMake 自动完成）
"D:/Qt/6.8.0/msvc2022_64/bin/lrelease.exe" app/translations/edithere_en.ts
```

改完 `tr()` 或 `.ts` 之后跑一次一致性检查，它会用 `lupdate` 现场重抽一遍，比对上下文与漏译、
失效条目：

```bash
python scripts/check-translations.py --qt D:/Qt/6.8.0/msvc2022_64
```

`lupdate` 需要完整的 Qt 安装，所以这条检查只在本地（以及有 Linguist 的构建上）作为 CTest 的
`translations` 注册；CI 用的是没有 Linguist 的精简 Qt，它跑不了。**"改了 `.ts` 忘了
`lrelease`"由另一条与工具无关的检查兜底**：`scripts/check-packaging.py` 逐条比对 `.ts` 的原文
与译文是否真的出现在 `.qm` 里（`.qm` 把源串存成 UTF-8、译串存成 UTF-16BE，因此可以直接查），
它作为 CTest 的 `packaging` 在 CI 里也跑。

CMake 在找得到 Qt Linguist 工具时用 `qt_add_translations` 现场编译 `.ts`；CI 的精简 Qt
安装没有这些工具，因此 `app/translations/built/edithere_en.qm` 作为预编译产物一并提交，
构建时回退到它。**修改了 `.ts` 之后必须重新生成这个 `.qm` 并一起提交**，否则发布包里的
英文界面不会更新：

```bash
"D:/Qt/6.8.0/msvc2022_64/bin/lrelease.exe" app/translations/edithere_en.ts -qm app/translations/built/edithere_en.qm
```

## Qt 自带控件的翻译

文件对话框、消息框的标准按钮、`QColorDialog` 这些是 Qt 自己的字符串，由 Qt 随版本发布的
`qtbase_<locale>.qm` 提供，和 `:/i18n/` 里的应用翻译无关。它们不在可执行文件里，得靠部署
时摆到 `QLibraryInfo::TranslationsPath` 下；找不到就静默退回英文，界面会变成"我们的文案是
中文、Qt 的按钮是英文"。

两处坑：

- **文件名随部署方式变**。Qt 安装目录里同时有 `qtbase_<locale>.qm`（真正的目录）和
  `qt_<locale>.qm`（只有几十字节的元目录，列出依赖），而 `windeployqt` 会把前者**改名**成
  `qt_<locale>.qm` 放出去。`installLanguage()` 因此按 `qtbase_*` → `qt_*` 的顺序依次尝试。
- **`qttranslations` 是 Qt 仓库里独立的归档**，`--archives qtbase qtimageformats` 装不到它。
  CI 与本地安装命令都必须带上 `qttranslations`，否则 `.tools/qt/<ver>/<arch>/translations/`
  根本不存在，`scripts/package-windows.ps1` 会因为找不到中文目录而直接报错中止。

界面只提供两种语言，所以打包时只放中文那一个文件就够了（英文是 Qt 的默认文案，不需要翻译）。
`package-windows.ps1` 在 `windeployqt --no-translations` 之后单独把
`translations/qtbase_zh_CN.qm` 拷进 `translations/`，只增加约 130 KB；macOS 由 `macdeployqt`
默认部署，命名是 `qtbase_*`，两种查找都能命中。

## 新增一种语言

1. 在 `app/settings.h` 的 `LanguageMode` 加一项，`settings.cpp` 的 `languageName()` /
   `parseLanguage()` 加对应的 locale id；
2. `app/i18n.h` 的 `languageDisplayName()` 加该语言的自称，`i18n.cpp` 的 `systemLocale()`
   在需要时识别它；
3. `lupdate` 生成 `app/translations/edithere_<locale>.ts`，翻译后重新生成 `.qm`；
4. 把语言加进 `settingsdialog.cpp` 的语言下拉框。

不想改代码的临时办法：把 `.ts` 用同一套流程生成，`.qm` 命名为
`edithere_<locale>.qm` 放进 `:/i18n/`，界面语言在 `settings.ini` 里写
`appearance/language=<locale>` 即可加载。

## 界面语言怎么选

`AppSettings::language` 有三态：

- `System`（默认）——跟随系统。`zh*` 系统用简体中文，其余一律用英文；
- `SimplifiedChinese` ——简体中文；
- `English` ——英文。

选择会立即生效（设置对话框里切换即可看到变化），并写入 `settings.ini` 的
`appearance/language`。取消设置对话框会回滚到打开时的语言。
