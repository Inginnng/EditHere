# 长截图实现参考

长截图保留现有 Qt 架构，Windows、macOS 和 Linux 共用菜单、预览、裁剪与拼接逻辑，平台层负责实时像素采集及滚轮输入。支持纵向和手动横向采集。

## 平台与权限

| 平台 | 实时采集 | 自动纵向滚动 | 条件 |
| --- | --- | --- | --- |
| Windows | 原生桌面像素 | 原窗口滚轮消息 | 支持普通桌面窗口 |
| macOS 14 及以上 | ScreenCaptureKit | CoreGraphics 定向滚轮事件 | 采集需要屏幕录制权限；自动滚动还需要辅助功能及事件投递权限 |
| Linux X11 | XGetImage | XTest 滚轮 | 自动滚动需要 XTEST 扩展；缺少扩展仍可手动滚动 |
| Linux Wayland | ScreenCast Portal + PipeWire 授权屏幕流 | 暂未启用 | 构建需要 PipeWire 1.0.4 及以上；桌面需要 ScreenCast Portal，并提供可对应所选屏幕的几何信息 |

macOS 使用选定屏幕的原生像素与 Retina 比例转换选区，辅助功能识别仍使用系统的逻辑坐标；采集过滤器排除 EditHere 自身窗口。X11 锁定所选屏幕的原生坐标与原窗口进程，自动输入后恢复鼠标位置；窗口没有提供进程信息时仍可手动采集，但不发送自动滚轮。Wayland 锁定授权的屏幕流，在无法唯一对应显示器时明确拒绝，不能猜测为主屏；开始授权后复用会话，返回原选区保留授权，完成或取消整次截图时关闭会话。没有输入权限不会禁用手动长截图。

Wayland 目前需要用户手动滚动。系统的屏幕共享授权不等于鼠标输入授权，自动滚动还需要接入 RemoteDesktop Portal；当前未申请该额外权限。屏幕共享被撤销或屏幕布局变化会停止采集并提示重新选择。

## 已查阅的开源实现

- [ShareX · ScrollingCaptureManager.cs](https://github.com/ShareX/ShareX/blob/73967140f4fd64ca4b93203ae8ad5ac05ade9aaf/ShareX.ScreenCaptureLib/ScrollingCaptureManager.cs)：采集和拼接逐轮推进，以滚动间隔等待页面，比较连续截图确认到底；匹配时避开两侧边缘及固定底栏，区分完全成功、部分成功和失败。
- [deepin-screen-recorder · pixmergethread.cpp](https://github.com/linuxdeepin/deepin-screen-recorder/blob/88d7a015ea4c043389fe5c7658779ca5aebf7974/src/utils/pixmergethread.cpp)：先检测固定顶底栏，再用 OpenCV 模板匹配定位重叠内容，对不可信的匹配明确报错。
- [wayscrollshot · template_match.rs](https://github.com/jswysnemc/wayscrollshot/blob/master/src/stitch/template_match.rs)：先从模板得到位移候选，再用重叠区域的像素平均误差复核，同时比较次佳候选，拒绝歧义；于 2026-10-03 查看。

以上是设计和算法原理参考，EditHere 使用自行编写的 Qt/C++ 实现，没有复制这些项目的代码，也没有增加 OpenCV 运行依赖。ShareX 和 deepin 的早期参考固定到上述提交；本次同时复核 ShareX 当前实现和 wayscrollshot。

ShareX 当前的逐行精确相等及历史位移猜测，不能解决少量动画和跳回旧内容时的定位问题，因此没有采用其猜测回退。本次借鉴模板候选再密集复核的流程：快速采样产生候选，原始像素消歧允许小范围局部变化；匹配不到相邻视口时，利用已保存原图行的纹理索引重新寻找位置，再跨切片读取实际像素验证唯一重叠。切片只是完整原图的储存方式，右侧缩略图不参与识别。没有可验证重叠、纯空白或无法区分的重复图案仍会拒绝，不以猜测位移填补缺失内容。

## 在 EditHere 中的取舍

交互参考 [PixPin 长截图说明及动图](https://pixpin.cn/docs/capture/long-capture)：固定屏幕位置的选区、实时整图缩略预览、绿色当前视口、开始/停止、沿轴移动选区和两端裁剪。EditHere 从当前位置开始，可向上或向下扩展，回访已采集内容只更新当前位置而不重复追加；横向模式可左右滚动或拖动水平滚动条。默认手动滚动，停下滚动时继续等待，由用户完成。自动向下滚动和反向自动裁剪均默认关闭。

原冻结选区窗口隐藏后，选区外显示半透明灰色遮罩，空心边框标出真实采集范围。框内鼠标穿透到原应用；紧凑工具栏位于选区下方，滚动方向、自动滚动、裁剪、开始/停止、编辑、贴图、保存、关闭和复制在同一行。菜单跟随应用的浅色、深色或系统主题，编辑、贴图、保存、裁剪、复制和关闭复用普通截图及编辑器的相同图标；工具窗未获得焦点时也允许显示悬停说明。

右侧独立预览只在运行时显示，绿色方框标记当前已匹配视口。纵向预览宽度固定为 196 逻辑像素，新增内容向上下扩展，不能因长图增长而缩小整张图片；横向预览固定高度并沿水平方向扩展。到达屏幕边界后仅显示并跟随当前视口附近的原图区域，缩放比例保持不变。预览只分配屏幕大小的图像，即使原图长达 200 万像素也不建立相同高度的 Qt 位图。尺寸右侧的移动手柄在运行时只沿采集方向移动；拖动过程中暂停采样，释放后沿已截取的长图继续追加，保留现有长度、裁剪状态与原始像素。停止后可自由移动并拖动边缘调整大小。停止会取消本轮结果；再次开始从当前画面新建一轮。实际更改尺寸或方向也会清空本轮拼接，单纯移动选区不会清空。

剪刀菜单的上/下（横向模式为左/右）按钮直接裁去当前视口对应边界以外的原始像素；采集可以继续。最终编辑、复制、保存及贴图均使用裁剪后的像素，预览标记不会进入结果。保存通过普通保存对话框选择路径和格式。可选反向自动裁剪沿初始增长方向裁去回滚的部分，回到单个视口长度后重新判断方向。默认方向和自动裁剪也可在设置中配置。横向自动滚动未启用，因为现有平台接口发送纵向滚轮。

手动模式约每 60 ms 采样一次。滚动途中的样本有高可信重叠时立即更新，预览保持固定比例并标明当前视口；较低可信的近似匹配仍等画面停稳后再判断。滚动过快导致没有重叠时不会结束采集，而是提示用户稍微往回滚动；回到已截内容后可通过重新定位恢复拼接。进度窗已排除在屏幕采集之外时，采样期间不再反复隐藏。

采集选区使用屏幕原生像素，避免逻辑坐标在高缩放显示器上造成错位。页面滚动后连续采样确认停稳，再交给拼接器。手动模式不发送滚轮、不抢回页面焦点，连续没有变化时继续等待；自动模式向开始时确定的同一个窗口发送滚轮，一次没有变化会再确认一次，不能匹配与已经到底分别处理。切换模式会废弃旧轮的待处理回调，避免取消自动后继续滚动。

采集区没有空间放进度窗时，每次采集及投递滚轮前暂时隐藏控件。Chromium 会通过 [`WindowFromPoint` 重新路由滚轮](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/ui/base/win/mouse_wheel_util.cc)，直接向浏览器发送消息仍可能被覆盖其上的窗口拦住；这一行为通过真实浏览器页面验证。

拼接只在两端加入有可信重叠的新增内容，已覆盖部分只更新视口；固定顶栏保留一次、固定底栏放在结果末尾。低纹理和重复图案造成的歧义必须拒绝，不能用历史位移猜测。普通模式达到 32767 像素边长、3200 万像素或 600 帧上限时暂停并保留已拼接内容。设置中启用「超长截图」后，以临时磁盘切片储存原始像素，不受 600 帧限制，单轴最长 200 万像素。超过普通图像上限后，保存使用分块 PNG 导出，无须在内存中生成整张图片。超过编辑器的 32767 像素边长或 3200 万像素限制时，编辑、复制和贴图不可用，保存 PNG 仍可使用。超大图片的实际可查看性还取决于系统内存及图片软件。没有任何新增内容时不会把首帧当成长截图交付。

## 验证入口

`scrollstitch_tests` 检查拼接结果和拒绝条件；`scroll_controller_tests` 检查鼠标按钮启动、失败后原位置重试、停止、取消和结果交付；Windows 的 `scroll_platform_tests` 使用另一进程的真实窗口检查目标选取、滚轮投递及桌面像素采集。原生控制器用例从 `Controller::capture()` 的全屏截图开始，框选后点击工具栏，而非只测试快捷键。Linux 的 `linux_platform_tests` 在 Xvfb 中使用另一进程的 X11 窗口验证实时像素、上下滚轮、目标身份与输入扩展降级；`scroll_wayland_tests` 使用测试 Portal 和可注入的视频源验证授权会话及原生像素映射。

当前开发环境可运行 Windows 和 Ubuntu/WSL 的构建与测试；没有 macOS 主机，也没有可供授权的真实 Wayland 桌面。macOS 的本机编译、Retina 实测与 Wayland 的真实桌面流验收仍须在对应系统完成；测试 Portal 通过不代表真实桌面已验收。

普通截图的既有 `capture_tests`、`ui_tests` 继续作为相关回归检查。真实桌面的测试不能用 `-platform offscreen` 代替。

浏览器验收可打开 `tests/fixtures/scroll-browser.html`，设置 `H2D_SCROLL_BROWSER_TEST=1` 后运行 `scroll_controller_tests realBrowserProducesCompleteImage`；该用例使用实际 Windows 滚轮和屏幕像素，核对 60 行正文、固定栏及最终尺寸。默认 CTest 不运行需要手动打开浏览器页面的用例。
